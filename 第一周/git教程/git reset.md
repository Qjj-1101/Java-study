# Git Reset 三种核心操作笔记（可直接复制到Marktext）

## 一、核心作用

调整本地分支 `HEAD` 位置，撤销「暂存区修改」或「本地提交记录」，不影响远端仓库。

适用场景：误删文件、误提交、push 失败后调整本地状态

## 二、操作对比表

| 命令格式                     | 作用层级           | 核心效果                                        | 适用场景                       | 安全程度 |
| ------------------------ | -------------- | ------------------------------------------- | -------------------------- | ---- |
| `git reset [文件名]`        | 仅操作「暂存区」       | 撤销指定文件的暂存状态（如 `git add` 后的删除/修改），工作区、分支不变   | 删文件后 `git add` 了，想撤暂存再恢复文件 | 最安全  |
| `git reset --soft HEAD^` | 操作「本地分支（HEAD）」 | 回滚到上一个版本，暂存区和工作区的修改全部保留，`git status` 显示暂存状态 | 提交错了，想保留代码修改重新提交           | 安全   |
| `git reset --hard HEAD^` | 分支+暂存区+工作区     | 彻底回滚到上一个版本，清空所有未提交的修改（删除/新增/编辑）             | 提交后发现错误，想彻底恢复到修改前状态        | 高危   |

## 三、实操案例（结合删除文件场景）

### 场景1：撤销暂存的删除操作（无模式）

1. 操作流程：删文件 → `git add 文件名`（暂存删除）→ 想恢复文件

2. 执行命令：
   `# 撤销暂存的删除操作` `git reset test.txt` `# 恢复文件到工作区` `git checkout -- test.txt`

3. 验证结果：`git status` 无提示，工作区重新出现 `test.txt`

### 场景2：撤回提交但保留删除操作（--soft 模式）

1. 操作流程：删文件 → `git add + git commit` → push 失败 → 想撤回提交但保留删除

2. 执行命令：
   `# 回滚到上一个版本（删除前），保留暂存区的删除操作` `git reset --soft HEAD^`

3. 验证结果：`git status` 显示 `deleted: test.txt`，可修改后重新 `git commit`

### 场景3：彻底回滚删除操作（--hard 模式）

1. 操作流程：删文件 → `git add + git commit` → push 失败 → 想彻底恢复文件

2. 执行命令：
   `# 一键回滚到删除前的版本，清空所有修改` `git reset --hard HEAD^`

3. 验证结果：工作区重新出现 `test.txt`，`git log` 看不到删除的提交记录

⚠️ 警告：`--hard` 会清空未提交的修改，且无法恢复！执行前务必确认不需要这些修改

## 四、关键注意事项

1. 「HEAD^ 含义」：代表当前版本的「上一个版本」，`HEAD^^` 代表上上个版本，也可以用 commit ID 精准定位版本（通过 `git log --oneline` 查看 commit ID）。

2. 「和 git checkout 的区别」：
   `git reset`：调整暂存区/分支版本，侧重「重置状态」；

3. `git checkout`：恢复工作区文件，侧重「还原文件」。

4. 「不影响远端」：`reset` 只修改本地仓库，若已 push 到远端，不要用 `reset` 回滚（会导致本地和远端版本不一致）。

## 五、安全操作建议

执行 `reset` 前，先执行 `git log --oneline` 记录当前 commit ID，万一回滚错了，可通过 `git reset --hard [commit ID]` 恢复。
