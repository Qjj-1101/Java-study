### 🧱 1. 基础架构：异常的分类

在学习具体语法前，你必须先理解 Java 异常的“族谱”，这决定了你后续处理方式的选择：

- **Error（错误）**：JVM 无法解决的严重问题（如内存溢出）。**不需要**我们编写代码处理，程序通常会直接挂掉。
- **Exception（异常）**：程序运行中可能发生的一般性问题。这是我们处理的重点，又分为两类：
  - **编译时异常（Checked Exception）**：在编译阶段就必须处理，否则代码根本跑不起来（如 `IOException`）。**必须**处理。
  - **运行时异常（RuntimeException）**：编译时检查不出来，只有运行时才报错（如 `NullPointerException`）。**可以**不处理，但发生后程序会终止。
    
    

### ⚔️ 2. 核心对决：try-catch vs throws

这是处理异常的两种主要策略，你可以理解为“自己消化”和“甩锅”。

#### 🛡️ try-catch-finally（自己处理）

这是“捕获并处理”模型。你预感到某段代码可能会出错，就用 `try` 把它圈起来，一旦出错，立刻跳转到 `catch` 块进行善后。

- **try 块**：包裹可能出现异常的代码。
- **catch 块**：捕获特定类型的异常并处理（可以有多个，按**子类在前，父类在后**的顺序排列）。
- **finally 块**：**无论是否发生异常，最后一定执行**。通常用来释放资源（如关闭文件流、数据库连接），哪怕前面有 `return` 语句，`finally` 也会执行。



#### 📤 throws（声明抛出）

这是“推卸责任”模型。如果你不想在当前方法里处理异常，可以在**<u>方法声明处</u>**使用 `throws`，告诉调用者“我这个方法可能会抛出这种异常，你调用我的时候得自己处理”。

- **适用场景**：主要用于编译时异常，或者你觉得这个异常应该由调用者来决定如何处理。
- **注意**：如果一直往上抛，最终会交给 JVM 处理（打印错误信息并终止程序）。



###### ✂️ 3. 实战演练：自定义异常

JDK 自带的异常类（如 `ArithmeticException`）虽然多，但很多时候无法精准描述我们业务逻辑中的错误（比如“用户名已存在”、“余额不足”）。

这时候，就需要**自定义异常**。

- **为什么要自定义？**  
  为了更清晰地表达业务问题，方便调用者精准捕获并给出友好的提示。
- **如何定义？**
  - **继承 `Exception`**：如果你希望这是一个**编译时异常**（强制调用者处理）。
  - **继承 `RuntimeException`**：如果你希望这是一个**运行时异常**（不强制处理，发生概率低或属于编程错误）。
- **核心步骤**：写一个类继承上述父类，并提供空参和带参（`String message`）构造器。

### 📝 总结与对比

为了帮你更好地记忆，我整理了一个对比表格：

| 关键字/结构    | 作用        | 使用位置  | 备注                  |
|:--------- |:--------- |:----- |:------------------- |
| throw     | 主动抛出异常    | 方法内部  | 后面跟的是异常对象           |
| throws    | 声明可能抛出的异常 | 方法声明处 | 后面跟的是异常类型，可以跟多个     |
| try-catch | 捕获并处理异常   | 代码块   | `finally` 块中的代码总会执行 |



1.throw更像是一个动作。 （把throw比作”扔炸弹“，那么throws就是”贴危险标签“）

2.throws是放在类的方法声明处，有动作就会有异常，然后抛出异常。

3.try：监控区

            把可能出问题的代码包裹起来。

            逻辑：程序正常运行时，会按照顺序跑try里面的代码。一旦在try块里执行到了throw（或者空指针等运行时错误），程序会立刻停止try块里剩下的代码，然后直接去找后面的catch。

4.catch：捕获区

                盯着try块，看它有没有抛出特定类型的异常

                catch（），括号里会声明能够处理的异常类型

     如果，try抛出的异常和括号里声明的异常类型匹配，catch就会接着该异常，然后执行catch黎曼的代码。

多态性：一个try可以跟多个catch

3.finally：善后区

            无论try里是正常运行还是出错跳到了catch，甚至是在try/catch里写了 return，finally的代码一定会执行。

    用途：专门用来做清理工作，比如关闭数据库连接，关闭文件流，防止资源泄露。
