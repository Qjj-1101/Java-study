HashMap学习

1.HashMap底层 :Node数组     transient Node<K,V>[] table;

2.核心方法：put（K key，V value）

 当调用put方法时，内部操作：

1.算哈希：拿key值算一个哈希值

2.由这个哈希值经过运算，找到这个数据应该放在数组的哪个下标里面

3.放进去

       （1）如果table[] 还是空的，直接放进去

       （2）如果table[] 里面存在该数据（哈希碰撞） 重点！

                   那么：哈希碰撞有三点需要注意的！

          哈希碰撞：（有可能不同内容算出来的hashcode一样 这样就通过equals去判断就行）

    1.先看内存地址，如果两个put里面，key值相同（内存地址），直接覆盖

    2.再看哈希值，如果哈希值不一样，直接认定不是同一个

    3.最后看内容（equals）：如果哈希值一样，并且key.equals(key2)返回true，那么

                                                认定是同一个，直接覆盖。



| 场景        | hashCode() | equals() | 结果          |
|:--------- |:----------:|:--------:|:----------- |
| 同一个对象     | 一样         | true     | 覆盖 (最直接)    |
| 内容一样的不同对象 | 一样         | true     | 覆盖 (你的情况)   |
| 哈希碰撞      | 一样         | false    | 不覆盖 (变成链表)  |
| 完全不同的对象   | 不一样        | false    | 不覆盖 (存别的位置) |



总结：就是不一样的内容 但是算出来的哈希值一样 这样就会冲突 然后equals比较过后，发现内容一样就覆盖，不一样就形成链表



    如果是一样的内容，自然通过equals比较之后，哈希值肯定一样，这样就肯定覆盖了



但是当自己在类里面写的时候

如果重写了equals方法，就必须重写hascode方法 不然创建两个对象之后，hascode肯定不一样，

- 如果 `equals` 相等但 `hashCode` 不等，HashMap 会把它们当成两个完全不同的东西，或者导致 `get` 不到数据。

### 🗺️ HashMap 核心知识地图

#### 1. 基本概念 📖

- **是什么**：基于哈希表实现的 `Map` 接口，用于存储 **键值对 (Key-Value)**。
- **核心特性**：
  - **无序性**：不保证元素的插入顺序（遍历时顺序可能和插入时不一致）。
  - **允许 null**：Key 最多允许 1 个 `null`，Value 可允许多个 `null`。
  - **非线程安全**：多线程环境下并发修改可能会导致数据不一致或死循环。**线程安全场景请使用 `ConcurrentHashMap`**。

#### 2. 底层数据结构 🧱

HashMap 的底层结构在 JDK 1.8 前后发生了重要变化，这是面试必问点：

表格

| JDK 版本       | 底层结构          | 说明                                  |
| ------------ | ------------- | ----------------------------------- |
| **JDK 1.7**  | 数组 + 链表       | 采用头插法，多线程扩容时容易形成环形链表（死循环）。          |
| **JDK 1.8+** | 数组 + 链表 + 红黑树 | 引入红黑树优化，采用尾插法，解决了多线程死循环问题（但仍非线程安全）。 |

- **链表转红黑树的条件**：
  1. 链表长度 **大于 8**。
  2. 数组长度 **大于等于 64**。  
     *(如果链表很长但数组太小，会优先选择扩容而不是转树)*

#### 3. 核心参数 ⚙️

表格

| 参数       | 默认值  | 说明                            |
| -------- | ---- | ----------------------------- |
| **初始容量** | 16   | 数组的初始大小，必须是 2 的幂次方。           |
| **负载因子** | 0.75 | 衡量 HashMap 填满程度的指标。           |
| **扩容阈值** | 12   | 计算公式：`容量 × 负载因子`。超过这个值就会触发扩容。 |

#### 4. 常用方法速查 🛠️

表格

| 方法                   | 作用              | 注意点                    |
| -------------------- | --------------- | ---------------------- |
| **`put(K,V)`**       | 添加/修改元素         | 如果 Key 已存在，会覆盖旧值并返回旧值。 |
| **`get(K)`**         | 根据 Key 获取 Value | 如果 Key 不存在，返回 `null`。  |
| **`remove(K)`**      | 删除元素            |                        |
| **`containsKey(K)`** | 判断是否包含某个 Key    |                        |
| **`size()`**         | 获取元素个数          |                        |
| **`clear()`**        | 清空集合            |                        |

#### 6. Hash 冲突与解决 🔄

- **什么是 Hash 冲突**：不同的 Key 计算出了相同的数组索引(就是hashcode一样)。
- **解决方法**：
  - **拉链法**：将冲突的元素用链表连接起来。
  - **红黑树**：当链表过长时（>8），转换为红黑树以提高查询效率（从 O(n) 优化到 O(log n)）。

#### 7. 扩容机制 (Resize) 📈

- **触发时机**：当元素数量超过 `容量 × 负载因子`（默认 16×0.75=12）时。
- **扩容过程**：
  1. 新建一个原数组两倍大小的新数组。
  2. 重新计算所有元素的索引位置（Rehash），并迁移到新数组。  
     *注：扩容非常消耗性能，如果能预估数据量，建议在初始化时指定容量。*

#### 8. ⚠️ 避坑指南 (非常重要) 🚫

- **Key 的要求**：作为 Key 的类，**必须重写 `hashCode()` 和 `equals()` 方法**。
  - *如果不重写，自定义对象会使用默认的内存地址比较，导致逻辑相等的对象无法命中缓存。*
- **线程安全**：绝对不要在多线程环境下共享同一个 HashMap 进行写操作。
- **初始化容量**：如果知道大概要存多少数据，建议初始化时指定容量，避免频繁扩容带来的性能损耗。
  - *公式：`初始容量 = 预估数据量 / 0.75 + 1`*

---

**💡 总结一句话**：  
HashMap 是基于 **数组+链表/红黑树** 实现的，利用 **Hash 算法** 快速定位数据。它是 **非线程安全** 的，Key 可以为 null，且 Key 的类必须重写 `hashCode` 和 `equals` 方法。
